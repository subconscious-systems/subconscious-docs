This page is for security, compliance, platform, and engineering teams reviewing a **customer-hosted** Subconscious deployment. Final vendor and audit treatment is determined by you and your auditor.

**OrangeLine-only** is a thinner review: you run our container on your GPUs. We are an image vendor, not the operator of your gateway. The rest of this page describes the **full inference system**.

## Short answer

- The API Gateway runs in your AWS, GCP, or Azure account. OrangeLine runs on GPUs you choose, which need not be in the same cloud.
- Prompts, completions, logs, keys, and operational data stay in your environment unless you share them for support.
- Subconscious does not host your production inference system and does not need inbound access to your VPC.
- A customer-installed [Ryvn Agent](https://ryvn.ai/docs/guides/ryvn-agent) in the gateway cluster pulls desired state over outbound HTTPS. That agent is persistent in-cluster. It is not inbound vendor access, and it is not a requirement that Subconscious hold cloud-account credentials.
- You control networking, access, monitoring, and when production updates apply, using Ryvn approvals, maintenance windows, and release channels.
- Review Subconscious as customer-hosted software and supply-chain risk, not as a hosted production service operating your inference environment.

See [How it works](/on-prem/how-it-works) and [Ryvn](/on-prem/ryvn/overview).

## Deployment model

- **API Gateway**: customer-facing entry point for agent traffic, keys, routing, usage, and context pruning visualization and intelligence.
- **OrangeLine**: GPU inference runtime (TIMRUN) you run as a Docker container.
- **Ryvn**: deployment platform for the gateway environment. It is not required to receive customer code, prompts, completions, or production inference data.

## Security review position

> The product runs in your cloud account. Subconscious does not host the production system, does not need inbound access, and is not intended to receive production prompts, completions, source code, or production inference data. Updates are customer-approved.

Four principles:

- Production inference traffic stays in your environment by default.
- The API Gateway and OrangeLine operate under your operational control.
- You choose when to approve and deploy new versions.
- Support access is optional, customer-approved, time-bound, and logged.

## Shared responsibility

**Subconscious** is responsible for secure development, release integrity, release notes, security patches, deployment guidance, and documenting optional telemetry or support access.

**You** are responsible for cloud-account security, cluster and GPU administration, IAM, networking, monitoring and incident response, backups, scanning the running environment, change management, and internal rollout.

**Together**: deployment planning, security review, gateway and OrangeLine configuration, initial routes, performance validation, scan-result review, upgrade planning, and incident investigation when you approve support.

## Data handling

The following stay in your environment unless you explicitly share them: source code, prompts and completions, inference requests and responses, API keys and user records, runtime and application logs, operational metrics, and route configuration.

Subconscious does not need default access to your repositories, source code, prompts, production logs, cloud credentials, databases, or identity-provider data.

Sharing for support should be customer-initiated or approved, limited to the issue, sent through an approved channel, redacted where appropriate, and time-bound.

## Telemetry

No customer-data telemetry by default. If you enable any, it should be documented, opt-in, limited to the stated purpose, configurable, and free of source code, prompts, completions, secrets, and API keys. You can keep Datadog, CloudWatch, or similar as the system of record.

## Support access

Subconscious does not require persistent access to your cloud account. When support is needed, use a model you already trust: screen share, temporary access, break-glass, time-bound console access, one-time credentials, or exported diagnostics. Approve, scope, log, time-bound, and revoke.

## Releases and supply chain

You should be able to review release notes and artifacts, approve updates, use maintenance windows, roll back, and keep production cadence. Subconscious should not force production upgrades.

Because the software runs in your environment, supply-chain assurance is the main review focus. During evaluation we can provide or work toward an architecture overview, data-flow diagram, shared responsibility matrix, release notes, signed images or checksums, SBOMs, vulnerability scan results, SDLC and release-approval notes, incident disclosure, and support-access policy.

You remain responsible for scanning the deployed environment. We can help interpret results and plan patches.

Restricted egress, private registries, and customer-managed mirrors are in scope for planning. Exact support depends on your environment. Gateway BYOC still needs outbound HTTPS from the Ryvn Agent. OrangeLine-only needs whatever your GPU host needs to pull the image.

## Hosted trials

Hosted or Cloud API trials are separate from customer-hosted production and should be assessed under their own data-handling terms.

## FAQ

### How should we think about SOC 2 and vendor risk?

The gateway and OrangeLine run under your access, monitoring, networking, and change-management controls. We can provide assurance materials. Your auditor decides treatment.

### Does Subconscious process or store our customer data?

Not in the standard customer-hosted production deployment. Data stays in your environment unless you share specific items for support.

### Does Subconscious require access to our cloud account?

No persistent account access. The Ryvn Agent you install pulls over outbound HTTPS. Additional support access is approved, scoped, logged, time-bound, and revoked.

### Who controls updates?

You do. We publish releases; you approve them.

### What is the main security risk we should evaluate?

Software supply-chain risk: how we build, sign, scan, document, and deliver artifacts that run in your environment. You can scan those artifacts yourself before approving a deploy.

### Is telemetry enabled by default?

No customer-data telemetry by default.

### What happens during an incident?

You own incident response. We support investigation when you ask, using access or data you approve.

### Can we run in a restricted environment?

We can plan for private registries, restricted egress, and semi-air-gapped workflows. Fully disconnected gateway BYOC is not the default Ryvn path because the agent needs outbound HTTPS to the hub.
